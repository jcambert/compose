# compose v0.2.0

`v0.2.0` is the first broad feature release after the initial npm package baseline. It keeps `compose` CLI-first while making the local UI, reusable application services, stronger diagnostics and large workspace scanner hardening available from npm.

## Highlights

- Optional local browser UI launched with `compose ui`.
- Bundled React UI assets served locally from `dist/ui`, without browser-side React CDN imports at runtime.
- Shared `src/app` application service layer for CLI and GUI adapters.
- Hardened `compose doctor` installation, PATH, npm, Docker and workspace diagnostics.
- Local config management with `compose config path/export/import/reset`.
- Terminal browser filtering and sorting for large workspaces.
- Scanner exclusions, symlink skipping and traversal guard rails for large source roots.
- Fixed local UI blank page caused by invalid generated JavaScript.

## New commands and workflows

### Local UI

```bash
compose ui
compose ui --workspace dev
compose ui --port 0
compose ui --skip-docker --no-open
```

The local UI binds to `127.0.0.1`, uses a generated local token, reuses the CLI application services and requires confirmation before command execution.

The UI assets are bundled during `npm run build` and packaged under:

```text
dist/ui/index.html
dist/ui/assets/*
```

### Config management

```bash
compose config path
compose config export --output compose-config.backup.json
compose config import compose-config.backup.json --yes
compose config reset --yes
```

`compose config` without a subcommand still passes through to Docker Compose for the selected project.

### Browser filtering and sorting

```bash
compose browse --filter api
compose browse --sort runtime
compose browse C:\Sources --filter monitoring --sort path
compose stacks . --filter worker --sort services --dry-run
```

Favorites remain first, and refresh/quit actions stay available even when a filter hides all stacks.

### Scanner guard rails

```bash
compose scan C:\Sources --exclude artifacts tmp-generated
compose scan C:\Sources --max-depth 6 --max-directories 100000 --max-entries 500000
compose scan C:\Sources --json --max-depth 5 > stacks.json
```

Scanner warnings are written to stderr so JSON stdout remains parseable.

## Fixed

- `compose ui` no longer serves invalid generated JavaScript when command output rendering joins stdout and stderr with newlines.
- The UI root includes a visible loading fallback instead of a fully blank page before React mounts.
- The React UI no longer requires browser access to `esm.sh` or another CDN at runtime.
- Large scans avoid common dependency, cache, generated and IDE folders by default.

## Remaining UI follow-ups

The UI remains intentionally lightweight. Richer service details and log/runtime streaming through Server-Sent Events are still follow-up work.
