# compose v0.2.1

`v0.2.1` is a post-`0.2.0` stabilization release focused on making the optional local UI more useful in daily work and making Docker Compose command failures easier to understand.

It keeps `compose` CLI-first. The browser UI remains optional, local-only, token-protected and backed by the same application services as the terminal workflows.

## Highlights

- Manage saved workspaces directly from `compose ui`.
- Edit an existing workspace path without recreating the workspace.
- Remove workspaces only after an explicit confirmation.
- Stream selected stack runtime updates through Server-Sent Events.
- Stream live `docker compose logs --follow` output from the local UI.
- Close the Live streams panel from its header or with `Escape`.
- Synchronize Live streams with the stack selected in the Stacks view.
- Clear stale stream output when the selected stack changes.
- Use themed scrollbars for stack lists and live output panels.
- Attach structured Docker Compose execution diagnostics to failed command results.
- Print actionable terminal diagnostics for unavailable Docker, missing Compose files and generic non-zero Docker Compose failures.

## Local UI workspace management

```bash
compose ui
compose ui --workspace dev
```

The Workspaces section can now create, update, select and remove saved workspaces from the browser. Mutations use token-protected local endpoints and the same local config file as the CLI.

Supported browser actions:

- create a saved workspace
- update the path of an existing workspace
- select the current workspace
- remove a saved workspace after confirmation
- refresh the stack scan after a workspace change

## Live runtime and logs

`compose ui` now exposes read-only live streams for the selected stack:

```text
GET /api/events/runtime?stackId=<stack-id>&intervalMs=5000
GET /api/logs/stream?stackId=<stack-id>&service=<service>&tail=200
```

The log stream runs Docker Compose in follow mode:

```bash
docker compose -f <compose-file> logs --follow --tail <tail> [service]
```

The UI can stop streams without killing the local UI server. When the selected stack changes, the panel stops old streams and clears stale output so logs from two stacks are not mixed.

## Docker Compose error reporting

Failed executions now carry a structured diagnostic object with:

- failure kind
- title and message
- generated command
- working directory
- Compose file path
- exit code
- actionable hints
- raw stdout
- raw stderr

Normalized failure kinds:

```text
docker-unavailable
compose-file-missing
compose-command-failed
```

Terminal execution with the default Docker runner prints a readable diagnostic summary before returning the underlying non-zero exit code.

## Compatibility

This release does not introduce breaking command syntax or a new configuration model.

`compose ui` remains:

- bound to `127.0.0.1`
- protected by a short-lived local token
- optional
- backed by shared application services
- explicit about command preview and destructive confirmation
