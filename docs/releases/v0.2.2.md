# compose v0.2.2

`v0.2.2` is a patch release after `v0.2.1`. It publishes the UI polish and repository guidance merged after the `v0.2.1` npm publication.

This release keeps `compose` CLI-first. The browser UI remains optional, local-only, token-protected and backed by the same application services as the terminal workflows.

## Highlights

- Add repository-level `AGENTS.md` contributor and agent guidelines.
- Hide the Live streams launcher while the Live streams panel is already open.
- Keep action group spacing consistent across top bar, hero, status, detail and compact action sections.
- Keep the package metadata synchronized as `@jc90100/compose@0.2.2`.
- Update the roadmap so the next product increment focuses on simplified Compose YAML service editing.

## Local UI polish

The Live streams panel received a small polish pass:

- the floating launcher is hidden while the panel is open
- the opened panel remains the single visible control surface
- spacing for action groups is aligned with the rest of the local UI layout

This keeps the local UI cleaner without changing the streaming API or Docker Compose command execution model.

## Repository guidance

The release adds `AGENTS.md` at the repository root. It documents:

- project structure
- build and validation commands
- coding style
- testing expectations
- commit and pull request guidelines

## Roadmap update

After `v0.2.2`, the next product increment is not command history or desktop packaging. The roadmap now prioritizes simplified Compose YAML editing for users who are not specialists in Docker Compose files.

Planned direction:

- guided forms for common service fields
- create, modify and delete service definitions
- YAML diff preview before saving
- validation before writes
- preservation of advanced or unsupported YAML sections
- local-only and token-protected file mutations through `compose ui`

## Compatibility

This release does not introduce breaking command syntax or a new configuration model.

`compose ui` remains:

- bound to `127.0.0.1`
- protected by a short-lived local token
- optional
- backed by shared application services
- explicit about command preview and destructive confirmation
